По ТЗ 18 §9.3 (пилотный запуск) и §9.4 (критерии готовности, контрольная точка F). ## 1. Рамки пилота

- Один филиал, 2–4 недели (план 11.1 п.7), параллельно со старой системой записи, без интеграции с ней (18 §17 п.10; план п.11.3).
- Роли в пилоте: Владелец, Директор пилотного филиала (или города), 2–3 Администратора, тестовые клиенты из сотрудников и 5–10 реальных клиентов по согласию.
- Ответственные по `reglament-sboya.md` п. 1 назначены до первого дня.
- Выкладка пилотной версии – по `plan-zapuska-i-otkata.md`; наполнение – `chek-list-napolneniya.md` для этого филиала.

## 4. Ежедневный ритуал пилота

Утро, Директор: `backup.log` за ночь (через техадмина) – без «ОШИБКА»; `/reports/reconcile` – чисто; лента событий; «Требуют решения» вчерашнего дня закрыты.
Вечер, Администратор: конец смены по `instrukciya-administratora.md` §14; замечания дня – в журнал пилота.
Раз в неделю, Владелец: журнал замечаний, решения по классам P0–P2, подтверждение умолчаний `docs/reshenia.md`, которые пилот затронул.

## 5. Замечания и их классы

Как в `reglament-sboya.md` п. 3: P0 – деньги, двойная бронь, неверные остатки; P1 – раздел не работает; P2 – одно устройство или сотрудник; P3 – пожелание. Пилот не закрывается при открытых P0 и P1. Каждое замечание: дата, сценарий (П1–П8), шаги, ожидание, факт, класс, кто проверил исправление и когда.

## 7. Расширение на остальные филиалы

После КТ F: по одному филиалу (или городу) в неделю по `chek-list-napolneniya.md` §1 шаги 4–22 для нового филиала; первые три дня нового филиала – ритуал §4 с участием Директора пилотного; ночная сверка и `backup.log` – ежедневно по всей сети. Откат отдельного филиала – статус `temporarily_closed` и старая запись, без отката системы.
