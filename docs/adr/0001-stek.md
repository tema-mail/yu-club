# ADR 0001. Стек и размещение

Статус: принято 01.11.2026 (техлид, N-02; решения владельца 01.11 по хостингу и менеджеру пакетов).
Основа: план 3.5, 3.6; ТЗ 17 §4, §10, §11; 20 §3.

## Контекст

- Нужна гарантия «один слот – одна бронь» при гонке, включая составные ресурсы (01 §8, 17 §10) – её должна давать база, а не код.
- Деньги, баллы и сертификаты – журнал со сторно, без правки задним числом (06 §4.4, 17 §9).
- Время – по зоне филиала, несколько зон в сети (01 §4, 09 §13).
- Фронт сайтов – Astro (правило владельца), острова – Preact.
- Исполнитель – один техлид с ИИ-агентами: один язык на всё, минимум движущихся частей.
- Хостинг сейчас – наш VPS Beget в РФ, позже перенос к заказчику (решение владельца 01.11). 152-ФЗ – данные в РФ (N-01).

## Решение

| Слой | Выбор |
|---|---|
| БД | PostgreSQL 16; расширения `btree_gist`, `citext`; `gen_random_uuid()` для ключей |
| Рантайм | Node 26 (чётная ветка, LTS), TypeScript, ESM. `Temporal` – встроенный в Node 26 (проверено: `typeof Temporal === 'object'` на v26.8.1) |
| Сервер API | Fastify 5 + `fastify-type-provider-zod`; схемы – Zod 4 в `packages/contracts`, OpenAPI генерируется из них (`@fastify/swagger`) |
| Доступ к БД | Kysely + драйвер `pg`; сложный SQL (`EXCLUDE`, `FOR UPDATE`, отчёты) – через `sql` Kysely, без ORM |
| Миграции | чистый SQL: `db/migrations/NNNN_name.sql` и `NNNN_name.down.sql`; раннер `db/migrate.ts`, таблица `schema_migrations(version, name, checksum, applied_at)`, advisory-lock на время прогона, контрольная сумма применённой миграции не меняется |
| Фоновые задачи | pg-boss (своя схема `pgboss` в той же базе) |
| Сайт и ЛК | Astro (SSR, адаптер `@astrojs/node`) + острова Preact (`@astrojs/preact`, `preact/compat` для переноса TSX макета) |
| CRM | отдельное приложение Astro + Preact, целиком за входом |
| Push | Web Push (VAPID), пакет `web-push`, service worker сайта |
| SMS кода входа | интерфейс `SmsSender` (K9), реализации `log` (стенд) и боевой провайдер РФ – выбор заказчика (R-18) |
| Пароли сотрудников | argon2id, пакет `@node-rs/argon2` (готовые бинарники, без сборки в образе) |
| Менеджер пакетов | **npm workspaces** (отклонение от плана: pnpm на маке нет). Рабочие области: `apps/*`, `packages/*`, `db` |
| Тесты | Vitest; интеграционные – на настоящей Postgres 16: локально `embedded-postgres` 16.x, в CI – сервис `postgres:16`; e2e – Playwright; гонка – k6 |
| Размещение | Docker Compose на VPS Beget (РФ): `api`, `site`, `crm`, `worker`, `postgres`. Внешний вход – **общий Caddy сервера**, мы отдаём только блок сайта (`deploy/Caddyfile`), http→https кодом **301** (`redir ... permanent`, не 308) |

### Конфигурация – только окружением (решение)

Ни одного адреса, пути или ключа сервера в коде. Переезд к заказчику = другой `.env` + `docker compose up`.

| Переменная | Где | Назначение |
|---|---|---|
| `APP_ENV` | все | `dev` / `test` / `stage` / `prod`; демо-данные запрещены при `prod` (19 §10.1) |
| `DATABASE_URL` | api, worker | роль `yu_app` (рантайм) |
| `MIGRATION_DATABASE_URL` | job миграций | роль `yu_owner` (владелец объектов) |
| `PUBLIC_SITE_URL`, `CRM_URL`, `API_URL` | все | внешние адреса, CORS, ссылки в push |
| `COOKIE_DOMAIN`, `COOKIE_SECURE` | api | куки сессий |
| `SESSION_PEPPER` | api | секрет для хеша токенов сессий и OTP (HMAC-SHA256) |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | api, worker, site | Web Push |
| `SMS_PROVIDER` (`log` / имя), `SMS_API_KEY`, `SMS_SENDER` | api | код входа |
| `BACKUP_DIR`, `BACKUP_RETENTION_DAYS`, `BACKUP_ALERT_URL` | backup | бэкап (S0-17) |
| `LOG_LEVEL` | все | pino |
| `TZ=UTC` | все контейнеры | процесс всегда в UTC; локальное время – только через K8 |

Валидация окружения – Zod при старте; нет обязательной переменной – процесс не стартует (код выхода 1, имя переменной в логе, значение – нет).

### Роли БД (решение)

- `yu_owner` – владелец схемы, гоняет миграции.
- `yu_app` – рантайм: `SELECT, INSERT, UPDATE, DELETE` на рабочие таблицы, на журнальные (`audit_events`, `ledger_entries`, `booking_versions`, `client_consents`) – только `SELECT, INSERT`.
- Роли кластера создаёт скрипт инициализации контейнера (`deploy/initdb/*.sh`, пароли из окружения), а не миграция: миграция `0001` только проверяет, что роли есть, и выдаёт права.

## Отвергнутые варианты

| Вариант | Почему нет |
|---|---|
| Supabase / Firebase | ПДн у стороннего облака (152-ФЗ, N-01); журнал «только вставка» и `EXCLUDE` неудобны через их API |
| Next.js / React SPA | против правила владельца «фронт – Astro»; SPA хуже для страниц филиалов и игр (12 §13). Исключение – ветка A2 плана 3.6, только письменным решением заказчика |
| Prisma / TypeORM | прячут SQL, `EXCLUDE` и `tstzrange` – через сырой SQL всё равно |
| Redis для блокировок слотов, отдельный брокер (RabbitMQ) | лишняя часть: гарантию даёт `EXCLUDE`, очередь – pg-boss в той же базе |
| pnpm | не установлен у владельца; выигрыш на 3–4 пакетах не стоит установки |
| Node 22 + `@js-temporal/polyfill` | Node 26 уже на маке и в образе; встроенный Temporal убирает зависимость |
| Свой Caddy в compose | на сервере уже общий Caddy; второй займёт 80/443 |

## Последствия

- `package.json` корня: поле `engines.node` поднять до `>=26` (сейчас `>=22.18`) – иначе на Node 22 нет `Temporal`. Делает оркестратор.
- Интеграционные тесты без Postgres не запускаются; моки базы для гонок и `EXCLUDE` запрещены (план 8).
- pg-boss создаёт свою схему при первом старте – стартовать его под `yu_owner` в job миграций (`boss.start()` с `migrate: true`), рантайм – `migrate: false`.
- Переезд к заказчику: дамп + `.env` + общий или свой Caddy; код не меняется.
- Боевой SMS-провайдер – отдельная реализация `SmsSender` после ответа R-18.
