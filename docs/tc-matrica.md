# Матрица контрольных сценариев TC-01…TC-20 (Э5)

Источник сценариев – `tz/20_…md` §10; привязка к этапам – `docs/plan-yu-club.md` §8 («Матрица TC → этап»).
Правило: у каждого TC есть хотя бы один интеграционный тест на настоящей Postgres, который проходит сценарий ТЗ
целиком в одном тесте и назван `TC-NN: …`. Куски по разным файлам (describe с номером, «(TC-NN)» в хвосте) – углы,
они остаются, но имени `TC-NN:` не носят. Страж – `tests/core/tc-coverage.test.ts`: падает, если у какого-то TC нет
такого теста или имя `TC-NN:` есть только в экранном спеке.

Уровни: **И** – интеграционный (vitest, embedded Postgres, `tests/**`), **Э** – экран (Playwright на моке,
`apps/crm/tests`, `apps/site/tests`), **С** – стенд (Playwright на живом API, `tests/e2e`).

Гонки TC-01…TC-04 (план §8): N параллельных соединений пула (`Promise.all` над `runOccupancyCommand`, по соединению
на попытку), после каждой гонки – SQL «ни одной пары пересечений по активным единицам и по времени клиента».
До Э5 тесты с именами TC-01…TC-04 в `confirm.test.ts` были последовательными (hold → hold → confirm); они оставлены
как углы без имени `TC-NN:`, гонки вынесены в `tests/booking/tc-races.test.ts`.
